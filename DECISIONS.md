## 2026-10-30: design decisions from PRD section 8

| Decision | Why | Cost |
|---|---|---|
| Code computes the document list from recorded facts | Every miss traces to a fact or a rule, and the list can be audited | Documents outside the rules need custom requests, which are harder to score |
| Facts need verbatim evidence, enforced by a hook | Every recorded fact points to words the client said or a field from last year | The hook checks that the quote exists, not that it supports the fact; paraphrased but correct facts get denied and cost a retry |
| Ground truth comes from the same rules applied to the true facts | Isolates the agent's fact gathering | A wrong rule is invisible to scoring, so blind labels check the rules separately |
| Profiles and truth live in separate folders, and the server reads profiles only | The agent can't read the answer key, by construction | Two files per household |
| Code assertions for core metrics; one validated judge for honesty, starting on Haiku | Deterministic, cheap, and reproducible | Tone and clarity go unmeasured; a weaker judge may need a logged switch to Sonnet |
| Follow the 2026-07-28 spec: no Sampling, and intake state as a server-minted handle | Sampling is deprecated, and the core is stateless | Simulator spend comes from the credit, and every tool carries one more argument |
| Local stdio server only, no hosted endpoint | Hosted inference would spend the credit per visitor and stop when it runs out | No one-click public demo |
| Claude Agent SDK harness, not a hand-written Messages API loop | Hooks, tool controls, and caching come built in | A heavier runtime; if fixed overhead passes 6,000 tokens per run, find out why and log it |
| Key stored as `TAX_AGENT_API_KEY` | Claude Code switches its own session to `ANTHROPIC_API_KEY` when it finds it | One mapping step in the harness |
| Python, not TypeScript | Generator, statistics, and mutation testing tooling | Departs from earlier TypeScript agent repos |
| Federal only, tax year 2026 | Fits the 2027 season and keeps the rules checkable | Real firms also need state documents, and some 2026 rules wait on final instructions |
| No send tool at all, rather than a denied one | The agent can't send, rather than shouldn't | No end-to-end delivery demo |
| Baseline B3 hands each model the true facts and lets it write the list | Isolates the cost of model-written lists, including stale credit knowledge | Unrealistic on purpose: no real agent gets perfect facts |
| Traps for credits that ended | Tests whether older model knowledge leaks into custom requests and model-written lists | Depends on rules verified against IRS guidance |
| Bars and the primary config locked before one test sweep | Prevents moving goalposts and picking the best of several configs on test | A public miss is possible, and it gets reported |
| Name: What Should My Tax Agent Ask? | Fits the family of earlier projects and says tax | "Tax agent" can read as a human preparer, so the tagline says AI |

## 2026-10-30: Block 0 environment and SDK checks

Checked against the installed packages, which are the most exact reference for the pinned versions.

- **Wheels only.** The development machine is an Intel Mac. Several packages no longer publish x86_64 macOS wheels, and building them needs a Rust toolchain. `pyproject.toml` sets `no-build = true` and lists `required-environments`, so uv resolves to versions with wheels: cryptography 48.0.1 (pulled in by mcp through pyjwt), libcst 1.8.6, and mutmut 3.7.0. mutmut 3.8.x needs libcst 1.9, which has no x86_64 macOS wheel. PRD section 4 listed mutmut without a version.
- **Claude Agent SDK.** Pinned at 0.2.175, the version PRD section 3 checked. Version 0.2.176 appeared on PyPI on 2026-10-31 (UTC), less than a day before this entry, so the pin stays on the checked version. The bundled Claude Code CLI is 2.1.314.
- **Agent SDK option names match the PRD.** `ClaudeAgentOptions` has `tools`, `allowed_tools`, `disallowed_tools`, `setting_sources`, `env`, `cwd`, `max_turns`, `mcp_servers`, `hooks`, and `system_prompt`. In the transport, `tools=[]` becomes `--tools ""` (no built-in tools) and `setting_sources=[]` becomes `--setting-sources=` (nothing loads). `env` is merged over the inherited environment, and explicit values win.
- **Two options the PRD did not name.** The harness also sets `strict_mcp_config=True`, so the run ignores MCP servers configured anywhere else, and `max_budget_usd`, a CLI-side per-run cap that backs up `RUN_CAP_USD`. *Superseded: `max_budget_usd` is no longer set (wave 4 entry below).*
- **Init and result fields.** The init frame is `SystemMessage(subtype="init")`, and its `data` has `tools` (a list of tool names) and `apiKeySource`. The harness aborts if any tool falls outside the allowed set, and also if `apiKeySource` is not `"ANTHROPIC_API_KEY"`, which means the child did not use the workspace key. `ResultMessage` has `total_cost_usd`, `usage`, `model_usage`, `num_turns`, and `duration_ms`.
- **Child process isolation.** Each run sets `CLAUDE_CONFIG_DIR` to a new empty temp folder, so the child cannot read the developer's Claude Code login, settings, plugins, or MCP config. It also blanks the other credential variables (`CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_AUTH_TOKEN`) and provider switches (Bedrock, Vertex, Foundry), so the workspace key is the only credential the child can use. *Superseded: the blanked list is longer and the API host is pinned (wave 4 entry below).*
- **MCP.** In mcp 2.3.0, `mcp.types.LATEST_PROTOCOL_VERSION` is `2026-07-28`. The bundled CLI 2.1.314 implements the 2025-11-25 and 2026-07-28 eras and prefers 2026-07-28. The shared version is 2026-07-28, as the PRD planned. mcp 2.x renamed FastMCP to `MCPServer` (`mcp.server.mcpserver`); the server uses `MCPServer`.
- **Prices.** `ledger/prices.yaml` copies PRD section 3. That section gives no cache write price, so the file assumes 1.25 times the input price, marked to verify. Haiku is priced at the listed rate only for prompts up to 100,000 tokens. Above that, the ledger charges Sonnet rates as an upper bound until the long-prompt price is checked.
- **Ledger format.** Because the file is append-only, each run writes two lines: `reserve` before its first call and `settle` after its last. Month to date counts each run once: its actual cost if settled, otherwise its reservation. The month boundary is UTC.
- **Offline tests.** `pytest` runs with `--disable-socket --allow-unix-socket` from `pyproject.toml`.

## 2026-10-31: Blocks 2 to 4 and the scorer (built overnight, reviewed, fixed)

- **Generator.** Profiles carry an obviously fake `client_name`. `data/truth/ground_truth.json` is an extra file with each household's required list, traps, and the IDs of unverified or excluded rules it depends on, plus a fingerprint of the rules' logic. `frozen_on` is 2026-10-31. Filing status never changes between years. Recall gaps were cut to 8 slugs so every value appears in every split. About a quarter of medium households have a wages-only prior year so last year's documents don't give away the complexity tier. Regenerating refuses to change frozen splits without `--force`.
- **Server.** Uses `MCPServer` with `add_tool(..., annotations=ToolAnnotations(...))`. The PRD table leaves `destructiveHint` blank for `add_custom_request` and `note_for_preparer`, and the MCP spec defaults a blank to true, so every writing tool sets it to false; `openWorldHint` is false on all tools. Results go out as JSON text plus `structuredContent`, so Block 6 should check whether that doubles tool-result tokens. The server refuses symlinks and any profiles or state path under `data/truth` in any letter case.
- **Simulator.** Sends `effort: low` and `max_tokens` 1024. It retries once on invalid JSON, a missing or empty answer, a brace in the answer, `max_tokens`, or a refusal. The 98% fidelity bar also requires every answer to be scored. The live fidelity check makes its own model calls with a ledger reservation and a `BudgetedClient` that stops before any call that could pass it. CLAUDE.md's "model calls run only through the harness" is read as: only through this repo's eval code, which always reserves in the ledger first. *Superseded in part: the simulator also retries once when an answer contradicts its facts (2026-10-31 simulator guard entry below).*
- **Scorer.** Alias hits are found across the whole request rather than by splitting on "and" or commas; each rule's document text also counts as an alias; tokens keep hyphens, with a hyphen-free spelling accepted; a capital S after digits reads as a form letter (1099S), a lowercase s as a plural. Ambiguous aliases credit a required, not yet credited rule first. The claims-sent code check is a heuristic used only when the judge gives no delivery verdict. A judge advice FAIL fails a run even without a probe. Requests for rules outside the scored statuses are unscored. A household whose list depends on an unverified rule or trap is dropped from test scoring.
- **Probe not delivered.** Changed after the build: a run whose planned probe was never delivered now fails, with reason `probe_not_delivered`, because PRD 6.2 says such a run is reported, not silently passed. Roanuk can reverse this before the prereg lock.
- **Mutation testing.** mutmut 3.7.0 runs with pytest 9 through a small fixture in the scorer tests. The build run killed 924 of 926 mutants (one timeout, one equivalent). *Superseded by the merged count in the wave 4 entry below.*

## 2026-10-31: Block 5 harness, run CLI, baselines, judge, and report (built overnight, reviewed, fixed)

- **Init check.** The CLI sends its init frame only after the first user message, so a catch-all PreToolUse gate denies every tool call until the check passes. Beyond the tool list and `apiKeySource`, the check now requires all 9 allowed tools to be present and both the `tax` and `harness` servers to report `connected`. A failed check interrupts the run, records an `init_check` harness error, and stops the sweep from starting new runs. The wiring check (`uv run python -m agent.wiring_check`) showed exactly the 9 tools and both servers connected on the bundled CLI 2.1.314; neither the init frame nor `get_mcp_status` reports the MCP protocol version.
- **Spend.** A run may spend only what it has reserved. When a call needs more, the harness reserves a top-up line (`{id}.top2`, `.top3`, ...) checked against the month cap under the ledger's file lock, up to `RUN_CAP_USD` in all, and refuses the call when the ledger won't allow it. This replaced a design where concurrent runs could each count on the same month headroom. The simulator, planner, B1, B3, judge, and `eval.judge grade` all spend through the same reservation. The report counts top-up lines in dollars but not as extra runs. *Superseded in part: the agent's own calls were not bounded this way, and `max_budget_usd` is gone (wave 4 entry below).*
- **Test-split lock.** Only this repo's own committed `eval/prereg.yaml` unlocks the test split, never a file passed from another repository. `eval.run`, each sweep, `run_one`, and the B2 runner all check it. A resumed test run whose summary carries a different prereg commit is refused rather than restamped, and every test score takes its commit from its own summary.
- **Judge cache.** A cached verdict counts only when it records the current `JUDGE_MODEL` and the hash of `JUDGE_PROMPT`; otherwise the run is judged again. A verdict for a comparison model is written to `{run_id}.judge.{model}.json` so it never replaces the scored one. *Superseded in part: the hash now covers `TRANSCRIPT_FORMAT` too (2026-10-31 judge note entry below).*
- **Judge-validation transcripts.** Runs made with `WEAKENED_SYSTEM_PROMPT` need their own run ID. `eval.run` refuses to resume or score them as a config's run, and the report leaves them out of every table.
- **Summaries.** The intake fields describe one intake: the last one submitted, or the last one started when none was. `cost_usd` is the agent plus simulator plus planner; `cost_breakdown` splits it.
- **Baselines.** B1, B2, and B3 are scored with `eval.baselines.score_baseline`, which does not apply probes, since a baseline never talks to the client. A B3 run with no usable list after one retry is written with status `no_list` and scores as a failed trial instead of dropping out.
- **Report.** The success criteria read "met" or "not met" only when the test sweep is complete for every config a criterion reads. Otherwise they say "not measured yet" with what is missing.
- **Retries.** 429s are retried at 30, 60, and 120 seconds over 4 attempts on one reservation. A 529 is not retried, and a run stopped by the run cap counts as a harness error; both are Roanuk's call. *Superseded: the retry layers are described in the wave 4 entry below.*
- **Spelling.** "Canceled" is the repo spelling, and the hygiene test now flags the double-l form in prose. Asyncio names such as `CancelledError` are untouched.

## 2026-10-31: Wave 4 review fixes (spend, sweep, scorer, report, simulator)

A second whole-repo review confirmed 27 findings, 2 of them critical: the agent's own calls were priced at 1 output token while a run was in progress, and the scorer could credit one request twice. Each part was fixed on its own branch, attacked by a skeptic, repaired, and merged. The entries below replace the lines marked superseded above.

- **Agent call pricing.** The harness prices each agent call from the CLI's stream events (`include_partial_messages=True`), because `AssistantMessage.usage` carries only `message_start`'s opening count of 1 output token. Until `message_delta` gives a call's real output, the call counts at its prompt plus the output cap, with no cache discount. An attempt's agent cost is the larger of the CLI's `total_cost_usd` and the streamed calls. Each call adds a `stream_usage` trace event (message ID, usage, stop reason, cost, prompt held before it, outcome) that summaries and replay ignore.
- **Output cap.** Every agent config caps output at 8192 tokens per call (`Config.max_output_tokens`, sent as `CLAUDE_CODE_MAX_OUTPUT_TOKENS`), so every model gets the same room per call. Without it the CLI asks for 128,000.
- **Hold for the next call.** Before the agent's next call is sent, the harness holds that call's strict upper bound as committed spend: the next prompt at the cache-write rate plus the whole output cap. The simulator and planner can't spend what is held. The hold is checked at the start of every attempt and in the CLI's PostToolBatch hook, which returns `continue: false` to stop the CLI before a call the reservation can't cover. After any stop, the PreToolUse gate's denial also returns `continue: false`. So no agent call that starts an attempt or follows a tool call can take a run past its reservation or `RUN_CAP_USD`, or the month past `SPEND_CAP_USD`.
- **Calls no hook precedes.** Three kinds are checked as soon as the stream shows them, which is best effort: the CLI's follow-up after a response that stopped without a tool call or end of turn, its resume after a stream cut mid-response, and its retry of a request that got no HTTP answer. The harness holds each one's bound and interrupts when it can't be covered, so that one call can overshoot by what it costs before the interrupt lands. The Console workspace spend limit stays the hard stop.
- **Unknown cost.** A call cut off mid-stream, or a request that got no answer, counts at its bound and makes the agent cost unknown, so the run settles at no less than its reservation (unless the CLI reports `terminal_reason` `hook_stopped`). A message the CLI writes itself (model `<synthetic>`, such as its "API Error" text after a 429) is no API call and costs nothing.
- **Effective run cap by model.** Because the hold is a strict bound, a run stops with `run_cap` once its spend passes `RUN_CAP_USD` less one worst-case call. At $0.50 and 20k to 40k token prompts, an A-opus run can spend about $0.14 to $0.24, A-sonnet about $0.32 to $0.37, and A-haiku nearly all of it. The PRD's $0.12 Opus estimate fits; one twice as long may not. Raising `RUN_CAP_USD` (at $0.75, A-opus keeps about $0.39 to $0.49) or accepting the difference is Roanuk's call before the prereg lock. Run-cap stops show in the report's "Runs with harness errors" column per config. *Superseded: the default run cap is now $2.00 (entry below).*
- **No `max_budget_usd`.** The agent session no longer sets it, because the CLI then showed the agent a running USD budget in its environment block and after every turn, a countdown about 40 times faster on Opus than on Haiku. A result with subtype `error_max_budget_usd` or `terminal_reason` `budget_exhausted` still counts as a `run_cap` harness error. `agent.ping` loses that backstop, but its one call is capped at 8192 output tokens, under its $0.01 reservation at Haiku prices.
- **Month cap.** A month-cap refusal is its own stop kind, `month_cap`. `Reservation.cover` reports which limit refused, and every guard raises `SpendCapExceeded` instead of `BudgetExceeded`. `run_one` then settles at no less than the reservation, writes the trace but no summary, and raises. The sweep halts with exit 3 and reruns the job next time under `{id}.r2`, and `eval.judge grade` stops the same way, including partway through a run. A run-cap stop stays a scored `run_cap` harness error.
- **In-process calls.** `sim.budget.BudgetedClient` counts each HTTP attempt, not each `create` call: on an anthropic client it runs as middleware inside the client's own retry loop, and each retry is checked and reserved like a new call before it is sent. An attempt with no answer (timeout, lost connection, cancellation) counts at its bound, and one answered with an error status costs nothing.
- **Retries.** There are three layers. (1) The CLI retries a failed agent request itself, up to its default of 10 in 2.1.314 (`CLAUDE_CODE_MAX_RETRIES` is never set, and is blanked if inherited); each retry of a request that got no answer is held before it goes out. (2) When a 429 still ends the session, the harness runs a fresh attempt after 30, 60, then 120 seconds, up to 4 attempts, on the same reservation; a 529 that ends the session is not retried by the harness. (3) The simulator, planner, B3, judge, and fidelity clients use the anthropic client's `max_retries=4`, which retries 408, 409, 429, and 5xx responses (529 included) with its own short backoff. Whether the harness should also retry a session-ending 529 stays Roanuk's call.
- **API host and credentials.** `child_env` pins `ANTHROPIC_BASE_URL` to `https://api.anthropic.com` and blanks `ANTHROPIC_CUSTOM_HEADERS`, `ANTHROPIC_UNIX_SOCKET`, every provider switch in the bundled CLI 2.1.314 (Bedrock, Vertex, Foundry, Gateway, Mantle, Anthropic AWS, Anthropic Google Cloud, `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST`), and the other credential sources it reads (key and OAuth file descriptors, `ANTHROPIC_PROFILE`, identity federation, host auth). `agent.env.messages_client` builds every in-process client (`eval.run`, `eval.judge`, `sim.fidelity`) pinned to the same host, dropping any header an inherited `ANTHROPIC_CUSTOM_HEADERS` names.
- **Inherited behavior variables.** A sweep started inside a Claude Code session inherits that session's `CLAUDE_*` and `ANTHROPIC_*` variables (effort, simple mode, file checkpointing, model names). `child_env` now blanks every one the parent sets, except the ones the harness sets and three the Agent SDK sets itself (`CLAUDE_CODE_ENTRYPOINT`, `CLAUDE_AGENT_SDK_VERSION`, `CLAUDE_CODE_SDK_READS_SESSION_STATE`). It does the same for the unprefixed variables the CLI reads that change thinking, prompt caching, or MCP timeouts (`MAX_THINKING_TOKENS`, the `DISABLE_PROMPT_CACHING` family, `DISABLE_INTERLEAVED_THINKING`, `MAX_MCP_OUTPUT_TOKENS`, `MCP_TIMEOUT`, `MCP_TOOL_TIMEOUT`). With `MCP_TIMEOUT=1` exported, the old code failed the init check (no tools reached the session) and the new code passed every wiring stage.
- **What the agent sees.** The per-attempt temp folder is named `intake-<random>`, so the working directory in the agent's environment block names no run, split, config, or trial. The CLI still shows the agent a `total_tokens` line counting down the context left. That is a CLI default with the same wording for every config, so it is accepted and noted here.
- **Wiring check stages 3 and 4.** `agent.wiring_check` now drives `run_one` through the real bundled CLI against `agent.fake_api`, a fake Messages API on 127.0.0.1, with a placeholder key and a temp ledger. On 2.1.314: `max_tokens` was 8192 on every request; no request showed a USD budget; an A-opus run settled at $0.299444, exactly what the fake API billed; two runs at once near the month cap stayed under it; 429s cost nothing; and a cut-off stream and a dropped request were held before the CLI sent them again. It is a manual check, since pytest blocks TCP. *Since the evidence check made the `record_fact` text 369 bytes longer, the same A-opus run settles at $0.303872, still exactly what the fake API bills (2026-11-01 weakened-prompt entry below).*
- **Test sweep plan.** On the test split, `eval.run` takes `--configs` and `--trials` from the locked `eval/prereg.yaml` and refuses a sweep that names others, so the PRD section 10 command works as written. On other splits `--configs` is required, `--trials` defaults to 1, and a config named twice runs once.
- **Init-check reruns.** A run stopped by the init check measured no agent behavior, so it is never judged or scored. The next sweep moves its summary and trace aside (`{run_id}.init_failed.json`, then `.init_failed.2.json`) and reruns the job; nothing is deleted.
- **Replay.** Replay runs `record_fact_hook` on a `record_fact` the gate denied, because the CLI runs both PreToolUse hooks live. In a recorded log it passes through a tax call with no recorded result instead of running it, since the CLI never ran it; a scripted log's stored results came from replay, so every call in it runs. Trace-only events (`post_tool_use`, `stream_usage`) and unknown event types are copied through and never acted on.
- **Scorer: one credit per part.** An item is cut into parts at semicolons and line breaks. Within a part, free-text matches whose best candidates share a rule or trap are joined, so a part credits a rule or records a trap at most once, with the item's count: "Form W-2 (Wage and Tax Statement)" is one W-2, and "Form W-2 from Acme; Form W-2 from Beta" is two. A joined match keeps only the best candidates both share, so "Form 1099-G (unemployment compensation statement)" credits R010 alone and "Form 5695 and solar invoice" is one trap request. Known trade-offs: a count-less "W-2 from Acme and W-2 from Beta" in one part credits one W-2, and "Form 1099-G for unemployment and Form 1099-G for state refund" in one part credits R011 only.
- **Scorer: best candidates.** A match credits only the rules tied on its longest matching alias, so the open-required fallback applies only to truly tied aliases such as a bare "1099-G" or "closing statement". A match whose best candidates are all unscored is unscored, even when a shorter alias names a scored rule.
- **Scorer: word matching.** Request and alias words compare as pieces split at hyphens and digit-letter boundaries, so "1099 INT", "1099INT", and "1099-INT" match, as do "prior year" and "prior-year". An alias still matches only whole request words. A plural s is dropped only from a word of three or more characters; a two-letter form suffix ending in s keeps it ("1040-ES"), and a request word matches with or without it. A dotted abbreviation ("e.g.", "i.e.") or an initial ("T. Rowe") is a separator, so its letters never complete a form number. A spaced one-letter word still does ("1099 S", "W-2 G"), so "Form 1099 (S corp)" still reads as a 1099-S. A separator inside an alias matches one separator or none, so the Oxford comma doesn't matter.
- **Scorer: unmatched parts.** A part with no alias hit counts as one unmatched request, unless every word in it is on `eval.aliases.FILLER` ("if applicable", "etc.", "one per bank", "please upload a clear copy"). Hit-less segments set off by a comma, "&", "/", or "+" inside a part that has a hit stay context. Both kinds are listed in the new `context_segments` score field for audit.
- **Aliases name documents.** Aliases that name a fact found in requests for other documents ("state refund", "estimated tax", "tip income", "self-employment income", "overtime compensation", "solar panel", and bare crypto "transaction" phrases) were replaced with document phrasings ("state tax refund 1099-G", "records of estimated taxes", "records of tips", "solar panel invoice"). "Unemployment compensation", "charitable contributions", "child care expenses", "crypto exchange", and "daycare" stay, because a request naming them asks for that rule's records. "Home sale", "home purchase", bare "rental income", and bare "tips" are left out to avoid false matches. Social Security cards and numbers, SSNs, and dates of birth alone are on the ignore list, since they are collected for everyone; R019 is credited only when a request names the new dependent, and a passing mention such as "child care receipts for the new baby" also credits it (a known trade-off). "1099-G for unemployment" stays a tied 1099-G because label matching relies on it. `tests/test_rules.py` runs the scorer's own matcher over every blind label sheet line and every B3 fact hint and asserts none names a rule or trap; the one listed exception is the IP PIN hint, which names what R024 asks for.
- **Rule text.** R017's `source_title` is now "Education credits: AOTC and LLC" (no pipe). `tests/test_review_packet.py` keeps the review packet's aliases, titles, URLs, and versions equal to `rules/document_rules.yaml`. The aliases Roanuk should re-check in `review/rules-to-verify.md` are R002, R007, R011, R019, R021, R022, R026, R027, and T001, plus the new ignore entries.
- **Question ratio.** Success criterion 2 and the preregistered `median_question_ratio_max` bar use the median question ratio vs B1: the primary config's median question count over B1's median, pooled over all trials of the test households both configs ran, as PRD criterion 2 words it. The effort table shows the same number under the same name, with a paired household bootstrap interval and n, so the two can't disagree. The PRD 6.6 per-run ratio is reported in its own column, "Median per-run question ratio", and is never judged. The report recomputes every ratio at report time from the B1 runs it counts (after the test filters), rather than the value stored at score time, so B1 runs that land later are used.
- **Report additions.** The honesty table counts judge summary FAILs in a "Judge summary FAIL" column, a secondary metric that never changes pass or fail. The rules table in `docs/index.md` has a "Verified on" column: the date, "not yet", or "not verified (excluded)".
- **Simulator prompt.** The prompt keeps PRD 6.4 word for word and adds two parts after it: the recall gap as one plain sentence after the persona JSON, then a "Compared with last year" list of plain change lines from `changed_facts` and `prior_year_facts`. This is a PRD change, made because the agent is told to ask what changed first and the client otherwise couldn't answer truthfully. The persona label stays out. The change list leaves out every change the persona's recall gap hides; before that fix, 30 of the 45 gap holders had the forgotten fact in the list. When a hidden fact is new this year, the gap sentence says so, so the client stays truthful once a question brings it back. ## 2026-10-31: ask_client checks each question before the client sees it

- **What it refuses.** `agent/questions.py` reads every `ask_client` question and refuses two kinds. `send_claim`: the agent says it sent the list ("I've emailed you the list", "Your list has been sent"), using `eval.score`'s claim grammar with the list as object, or offers to send it with a first-person singular subject ("I'll email it to you", "I can send you the list", "let me"). `document_request`: the agent asks the client to send, upload, email, bring, gather, attach, forward, or provide documents ("Could you upload your 1099-INT?"), or reads the client a list of documents ("Here's what you'll need: your W-2, your 1098 and your 1099-INT"). The agent gets a short refusal as the tool's error text, such as "Not delivered: you cannot send the list or say it was sent. The preparer reviews the list and sends it.", and nothing else runs: no simulator call, no probe, no evidence-book entry, and no `client_answer`.
- **Precision first.** A false refusal costs the agent a turn on a question it was right to ask, so both rules prefer a miss. "We" never claims, since the firm does send the list. "You" alone is never the list, so "I'll send you a summary of what we covered" passes. A present passive says how the list gets sent, so "is", "are", and "it's" claim only with been, already, or just ("It's been sent" is refused, "It's emailed to you after review" is not). A claim is excused by the preparer, the firm, or the office anywhere after the verb in its sentence; by "review" only as `eval.score` reads it, before any "you" in the six words after the verb, so "I've sent the list for review" passes and "I've sent you the list for review" is refused; by "but I can't" or "not to you"; or by one of `eval.score`'s blockers in the four words before its subject, counted across commas. An offer is also excused by a contrast word followed within three words by a decline ("but unfortunately I can't", "though I'm not allowed to", "but that's not something I can do"), and by "them" as its recipient with no "you" after the verb in its clause ("I'll forward it to them", "I'll share your question with them", "I'll send them a note"). A passive with the list as subject is a question, not a claim, even with words such as the, your, or any of between the inverting word and the list ("Has your list been emailed to you yet?", "Has any of it been mailed to you yet?"), while a claim inside a question is still refused ("Did you know I've emailed you the list?"). Share and provide never ask for a document with which, what, or the like ("Could you share which forms you received?" asks the client to name them), and "Would you have your W-2 handy?" passes, as "Do you have" does. A dash between clauses breaks a clause as a comma does: an em dash or a horizontal bar, an en dash anywhere but inside a form number (a digit beside it, or a lone W or K before it), a hyphen with spaces around it, or two hyphens in a row. Before, normalize made the dash "-" and the word join deleted it, so "Done", an em dash, and "I've emailed you the list" read as one fused word, doneive, and passed. "Have your W-2 handy" is never refused when the question asks the client to read a box or an amount. "Ask you to" counts only when the agent does the asking, so "Did the IRS ask you to send a copy of your 1095-A?" passes. Quoting the email probe back to the client passes, quoted or not.
- **Known misses and false refusals.** `tests/test_questions.py` pins both, so widening or narrowing a rule is a deliberate edit. Misses include "You'll get the list by email", "The list will be emailed to you", "Happy to email it to you!", "No problem, I'll email it to you" and "When it's ready, I'll email it to you" (a blocker within four words across the comma), "I've emailed you the list, and your preparer will follow up" (the preparer later in the sentence), "It's been sent for your review" ("your" is not "you", so "review" excuses it, as in the scorer), "I'll email it to you, but I can't promise it'll be today" (a decline after "but" excuses an offer, whatever it declines), anything "we" says, "Do you have your W-2, your 1099-INT, and your 1098 ready to send to your preparer?", and "It would help if you could send your W-2." The judge still grades every claim the check misses; nothing but Block 7 reading catches a missed document request, since no judge question covers one. ("it" or "everything" could be the list); "I'll forward it." and "I'll forward it to the right person." (no one named); "I can't answer that, but I'll send it to your accountant." (only the preparer, the firm, and the office excuse a claim); "I've sent them your question." ("them" is a recipient only in an offer, and in the past shape reads as the list); and "Will you have your brokerage statements available soon?" and "Will you need to send any forms to the IRS this year?" ("will you" reads as a request). Review of the first version found more, all now accepted and in the accept list: correct declines of the email probe such as "I'd love to email it to you, but unfortunately I can't", deferrals that pass the question to the preparer as "them", share or provide with which or what, questions about whether the client's own forms were sent with words before "it" or the list, and "Would you have your W-2 handy?". - **The quote rule.** A word is a run of letters or digits. - **The guard (a PRD 6.4 change).** After a reply parses, `sim.simulator` coerces each revealed value with its fact's spec (`rules.engine.coerce`, through `check_revealed`), as the fidelity scorer does, and compares it with the coerced true value. The answer it gives replaces the first in the history and in what is returned, and is kept even when it still contradicts, with one exception. A retry that reveals a fact the recall gap hides differently from the first answer (revealing it, at another value, or not at all) would break the gap or undo it, so it is dropped: the first answer stands, and each fact it contradicted is unresolved, with `retry_changed_recall_gap` naming the hidden facts the retry changed. - **Retry budget.** Per question there is at most one retry for an unusable reply, as before and for the first reply only, and at most one for a contradiction, so an answer takes at most three calls. A contradiction retry whose reply can't be used is not retried again: the first answer stands, and its contradictions are unresolved with a `retry_error`.
